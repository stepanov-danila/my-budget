# my-budget — спецификация проекта

Личное мобильное веб-приложение для учёта месячного бюджета. Работает офлайн,
без бэкенда, все данные хранятся локально на устройстве пользователя.

Этот документ — источник требований для последующей инициализации OpenSpec
(change `monthly-budget-tracker` будет создан на его основе).

## 1. Назначение

Пользователь ведёт учёт доходов и расходов по месяцам, распределяя суммы по
категориям, и в любой момент видит разницу между доходом и расходом за
текущий месяц.

## 2. Пользователь и платформа

- Один пользователь, без аккаунтов и авторизации.
- Мобильный веб (mobile-first), UI/UX оптимизирован под смартфон.
- Данные хранятся в `localStorage` браузера — офлайн, без синхронизации
  между устройствами.
- Валюта — российский рубль (₽), без мультивалютности.

## 3. Месяцы

- Месяц — основная единица данных: у каждого месяца свой набор категорий и
  сумм (категории per month, не общие на всё приложение).
- Месяцы отображаются табами в верхней части экрана, с горизонтальным
  скроллом/свайпом между ними.
- **Добавление месяца**: можно создать новый месяц с нуля (пустой набор
  категорий) либо перенести данные из предыдущего месяца — копируются и
  категории, и их суммы как стартовые значения, которые пользователь затем
  правит. *(Предположение — уточнить при необходимости.)*
- **Удаление месяца**: через диалог подтверждения (без Undo — это крупная
  потеря данных, подтверждение считается достаточной защитой).
  *(Предположение — уточнить при необходимости.)*
- Можно добавлять и удалять более одного месяца.

## 4. Баланс

- Разница между доходом и расходом текущего месяца всегда видна на экране —
  закреплённая (sticky) плашка сверху, не уезжает при скролле списка
  категорий.
- Показывается: сумма разницы, отдельно сумма дохода и сумма расхода за
  месяц.

## 5. Категории

- Два раздела: **Расходы** и **Доходы**, переключаются вкладками.
- Добавление категории: вручную (ввод названия) либо выбор из дефолтного
  списка (выпадающий список).
- При добавлении новая категория сразу занимает своё место в сортировке.
- **Сортировка** — по величине суммы, по убыванию (не по алфавиту).
  Пересчитывается при каждом изменении суммы или добавлении категории.
- **Удаление категории**: быстрое действие (например, свайп), без модального
  диалога, но с тост-уведомлением "Отменить" (Undo) на несколько секунд.
  *(Предположение — уточнить при необходимости.)*

### 5.1 Дефолтные категории расходов

Продукты · Кафе и рестораны · Транспорт · Дом и ЖКХ · Здоровье и красота ·
Одежда и обувь · Развлечения · Связь и интернет · Образование · Подарки ·
Путешествия · Прочее

### 5.2 Дефолтные категории доходов

Зарплата · Подработка/Фриланс · Подарки · Инвестиции · Возврат долга ·
Прочее

## 6. Ввод сумм

- В каждой категории хранится **итоговая сумма за месяц** (не список
  отдельных операций/транзакций).
- Ввод суммы — вручную (текстовое поле) либо слайдером; оба способа
  синхронизированы (движение слайдера обновляет цифру и наоборот).
- Диапазон слайдера по умолчанию: 0–50 000 ₽, шаг 100.
- Если пользователь вводит значение больше текущего максимума слайдера или
  утягивает ползунок к правому краю, максимум слайдера адаптивно
  увеличивается, чтобы вместить введённое/желаемое значение.

## 7. Визуализация

- Диаграмма по категориям (распределение расходов/доходов за месяц) —
  входит в объём, не блокирует MVP.

## 8. Тема оформления

- Переключение между светлой и тёмной темой.

## 9. Undo (отмена действий)

- Присутствует как минимум для удаления категории (см. раздел 5).

## 10. Вне рамок (не делаем)

- Мультивалютность.
- Многопользовательский/семейный доступ, авторизация, шаринг.
- Импорт из банка, интеграции с банковскими API.
- История отдельных операций (транзакций) внутри категории — хранится
  только итоговая сумма за месяц.
- Синхронизация между устройствами / бэкенд.

## 11. Технологический ориентир

- React + TypeScript + Vite, Tailwind для стилей, PWA-дружественная
  структура, персистентность через `localStorage`. Финальный выбор стека
  фиксируется на этапе OpenSpec `design.md`.
